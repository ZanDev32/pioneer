<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Agent → Shell wrappers | Scripts execute `pio` CLI commands; unvalidated project_dir could enable path traversal |
| Shell wrappers → Filesystem | Scripts check for platformio.ini but do not enforce workspace boundaries (MCP server does) |
| Shell wrappers → Serial hardware | upload.sh can flash firmware without the ask-before-flash gate that MCP enforces |
| Shell wrappers → npm/pip | Scripts do not install packages, but rely on `pio` being pre-installed by user |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Injection | Shell wrapper argument handling | mitigate | All scripts use quoted variables ("$VAR") to prevent word splitting and glob expansion; positional args are passed as separate arguments to pio, not interpolated into shell strings |
| T-01-07 | Spoofing | Missing platformio.ini validation | mitigate | build.sh, upload.sh, clean.sh, and test.sh verify `test -f "$PROJECT_DIR/platformio.ini"` before execution; reject execution if not found |
| T-01-08 | Tampering | Shell wrapper file modification | mitigate | Scripts are version-controlled in repo; SKILL.md (Plan 01) instructs agent to verify scripts exist in trusted assets/ path before execution |
| T-01-09 | Elevation of Privilege | upload.sh flashing without confirmation | mitigate | SKILL.md mandates ask-before-flash at the agent level; upload.sh prints WARNING about missing guardrails but cannot enforce agent-level confirmation — responsibility is on SKILL.md tier selection logic |
| T-01-10 | Information Disclosure | discover.sh enumerating serial devices | accept | Read-only enumeration via `pio device list`; no sensitive data; standard system utility |
| T-01-SC | Tampering | npm/pip/cargo installs | mitigate | No package installation in shell wrappers; scripts only invoke pre-installed `pio` binary |
</threat_model>
