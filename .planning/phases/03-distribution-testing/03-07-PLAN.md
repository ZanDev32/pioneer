<task type="auto">
  <name>Tag-triggered provenance publish job</name>
  <files>.github/workflows/ci.yml</files>
  <action>
    Add a `publish` job to the existing workflow. Do not add a second `on:` block or a duplicate `push` key: 03-06 already declares `push` with `branches: [master]` and `tags: ['v*']` plus `pull_request` and `workflow_dispatch`, so the tag trigger this job needs is already present — editing the existing `push` mapping is only acceptable if `tags: ['v*']` is missing, and then it is added to that same mapping. The job itself carries `if: startsWith(github.ref, 'refs/tags/v')` so it can never run from a pull request, an ordinary branch push, or a manual dispatch. Job permissions: `contents: read` and `id-token: write` only (provenance mints an OIDC attestation). `runs-on: ubuntu-latest` — a cloud-hosted runner is required for provenance.

    Steps in order: `actions/checkout@v7`; `actions/setup-node@v7` with Node 24, `registry-url: 'https://registry.npmjs.org'`, and `package-manager-cache: false` (a release build must not restore a stale dependency cache); `npm ci`; `npm run build`; `npm test`; a guard step running `test "${GITHUB_REF_NAME#v}" = "$(npm pkg get version | tr -d '"')"`; a step that derives the dist-tag into `$GITHUB_OUTPUT` (`--tag next` when the version contains a hyphen, empty otherwise); then `npm publish --provenance --access public ${{ steps.<id>.outputs.flag }}` with `NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}` set only on that step's `env`.

    Do not add a `workflow_dispatch` path to publishing (D-26) and do not publish from any local shell.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git tag → registry | a pushed tag is the only key to publishing |
| repository secret → workflow log | any echo or broad `env` exposure leaks a publish-capable token |
| OIDC token → transparency ledger | the minted attestation binds the artifact to a repository URL |
