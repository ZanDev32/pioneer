<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry -> devDependencies | A wrong version or a typosquatted package executes install scripts in CI and locally |
| test lane -> host OS | A test that reaches a real child process or network makes CI non-hermetic |
| opt-in e2e script -> default suite | A default-run e2e test breaks every machine without a PlatformIO project |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-01 | Tampering | handler `pio` invocation | high | accept | No handler tests are written here; plan 03 adds the child-process guard and routes the async branches through the shared executor. |
| T-3-02 | Tampering | `npm install` of vitest / coverage-v8 | high | mitigate | Exact 3.2.7 pins, `--save-exact`, lockfile commit, and the blocking-human package-legitimacy checkpoint (task 1) before install. |
| T-3-03 | Elevation of privilege | CI publish path | high | accept | No workflow in this plan; tag-only publish job with scoped permissions is plan 05. |
| T-3-05 | Denial of service | default `npm test` lane | medium | mitigate | `test:e2e` is a separate script; a static gate fails if the default test script references the UAT script. |
| T-3-SC | Tampering | npm/pip/cargo installs | high | mitigate | All packages are version-pinned; `[SUS]` vitest/coverage-v8 cleared by a blocking checkpoint; no other installs. |
</threat_model>
