<objective>
Cut the release candidate and run the milestone-gated manual host validation that automation cannot cover.

Purpose: D-20 gates manual host validation to milestone releases, and D-06/D-26 require the RC to be validated before `latest` moves. This plan produces the artifacts (version, changelog, checklist) and ends at the human gate that cuts `0.2.0` only after all three hosts pass.
Output: `0.2.0-rc.1` version, the `0.2.0` changelog section, `docs/host-smoke-test.md`, the `0.2.0` version write with its `v0.2.0` tag, and a recorded human sign-off.

Release sequence this plan sets up: tag `v0.2.0-rc.1` → CI publishes `0.2.0-rc.1` under `next` → humans run the checklist by installing `npx -y @zandev32/pioneer@next` in each host → `npm version 0.2.0` writes the version and creates the release commit + `v0.2.0` tag together (D-05) → push that commit and tag → CI publishes `0.2.0` as `latest`. The tag is never created against a different version: `npm version` writes the version and the tag in one step, which is exactly the equality 03-07's guard checks. Never re-tag or move a dist-tag by hand.
</objective>

| tag push → release | a tag is the release trigger and cannot be unpublished |
