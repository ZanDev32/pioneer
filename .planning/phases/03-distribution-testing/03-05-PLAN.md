<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tag push -> registry | A tag is the only credential-free action that can publish |
| workflow -> OIDC | `id-token: write` lets a job mint a provenance identity |
| PR code -> CI | Fork or PR code runs with repository secrets unless scoped |
| npm registry -> CI | A floating Inspector version executes postinstall code on the runner |
| workflow input -> opt-in e2e | A caller-provided project path is executed by the UAT script |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-01 | Tampering | handler `pio` invocation | high | accept | The seam is enforced and gated in plan 03; the protocol suite only calls pio_task_list and a pre-spawn PROJECT_NOT_FOUND path. |
| T-3-02 | Tampering | Inspector install in CI | high | mitigate | `npx --yes @modelcontextprotocol/inspector@2.14.0` exact pin, its own Node 24 job, and the blocking-human legitimacy checkpoint (task 1). |
| T-3-03 | Elevation of privilege | publish job reachability and permissions | high | mitigate | Publish job is gated on `startsWith(github.ref, 'refs/tags/v')`, workflow-level permissions stay `contents: read`, `id-token: write` is job-scoped, and the verify fails if `id-token` appears before the publish job. |
| T-3-06 | Tampering | tag/version drift | high | mitigate | Tag-to-package.json equality step runs before publish; a mismatch aborts the job (D-17). |
| T-3-07 | Spoofing | NPM_TOKEN exposure to PR runs | high | mitigate | Token is only exposed in the tag-gated publish job; no PR-triggered job references `secrets.NPM_TOKEN`; provenance uses short-lived OIDC. |
| T-3-SC | Tampering | npm/pip/cargo installs | high | mitigate | Inspector pinned and human-gated; PlatformIO installed by name from PyPI in the opt-in job only; npm ci uses the committed lockfile. |
</threat_model>
