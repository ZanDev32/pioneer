  <name>Protocol lane against the built bundle</name>
  <files>test/protocol/stdio-smoke.test.js, vitest.config.js, package.json</files>
  <behavior>
    - The test skips with a clear message when `dist/server.js` is absent, and fails (does not skip) when it is present but misbehaves.
    - `initialize` over stdio returns `protocolVersion === '2025-11-25'` and `serverInfo.name === 'pioneer'`.
    - NFR-1's startup bullet: that same `initialize` round-trip completes in under 2000 ms measured from process spawn to the response line.
    - `tools/list` returns exactly 12 tools whose names match the registered set and whose `inputSchema.type === 'object'`.
    - `tools/call` for `pio_task_list` returns `isError` falsy and text parsing to `{ running_tasks: [], count: 0 }`.
    - `tools/call` for `pio_build` with `PIO_WORKSPACE_ROOT` pointed at an empty temp dir returns `isError: true` and text parsing to `{ error: { code: 'PROJECT_NOT_FOUND' } }`.
    - The spawned server is always killed in teardown, including on assertion failure.
  </behavior>
  <action>
    Create `test/protocol/stdio-smoke.test.js`. Use the installed SDK client (`Client` from `@modelcontextprotocol/sdk/client/index.js`, `StdioClientTransport` from `@modelcontextprotocol/sdk/client/stdio.js`) with `command: process.execPath`, args `['dist/server.js']`, and an env carrying `PIO_WORKSPACE_ROOT`. Use it for the multi-request assertions (`tools/list`, `tools/call`). The SDK client does not expose the negotiated protocol version, so add one raw NDJSON round-trip for `initialize` only: write one JSON-RPC request line to a spawned bundle and read one response line, then assert `result.protocolVersion`. Take the elapsed time from that same spawn with `performance.now()` and assert it is under 2000 ms — NFR-1's startup bullet, measured on the artifact consumers actually run. That is a single frame, not a hand-rolled transport — do not build a second framing layer.

    Add a `protocol` project to `vitest.config.js` (`include: ['test/protocol/**/*.test.js']`, `testTimeout: 30000`) and a `test:protocol` script (`npm run build && vitest run --project protocol`). Leave the `test` and `test:coverage` scripts selecting only the `unit` and `integration` projects — D-25 keeps coverage over those two, and the protocol project must not be reachable from either script.
  </action>

    <fails_when>non-zero exit, `0 passed`, a skip message because `dist/server.js` is missing, or an assertion failure naming the tool count, `protocolVersion`, `PROJECT_NOT_FOUND`, or `running_tasks`</fails_when>
  </verify>
  <done>The protocol lane runs against the built artifact and asserts the handshake version, the 12-tool surface, and both a happy and a structured-error tool call.</done>
